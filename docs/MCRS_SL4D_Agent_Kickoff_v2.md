## 关于安慰剂根因排查的特别交代（本次任务最容易走歪的地方）

时移安慰剂 d=0.34 的异常必须找到根因。排查顺序（按先验概率）：

1. 事件时间聚集 + 板块动量自相关拖尾 → 画事件日历分布、事件后 20-60 日分段超额衰减曲线；
2. 基准构造耦合 → 用官方 `sw_daily` 口径重算，与 v1 自建成分聚合口径并列对比；
3. 对齐 off-by-one 实现 bug → 全事件自动断言。

**允许你动的**：数据源、指数口径、基准构造、日期对齐、缓存逻辑——一切"装置层"。
**禁止你动的**：C1-C5 定义、P1-P18、事件定义、去重规则——一切"信号层"。
判别法：如果某个改动会让"哪些 (板块, 日) 触发信号"发生变化（数据修复导致的除外），它就是信号层改动，禁止。如果你发现"只要把某阈值改成 X 安慰剂就过了"——那不是修复，是污染，立即停止并上报。

排查中每个决定记入 REPORT_v2.md 的 Decisions 节（改了什么、为什么、影响哪些数字）。若三个方向排查穷尽后安慰剂仍不过：停止，输出根因分析报告，等待人类裁决。不要发明第四种修法硬闯。
