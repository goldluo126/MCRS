## 硬性纪律（违反任一条即任务失败）

1. **SPEC v13.0.1 是唯一真相源，零回引可 grep 验证**。发现任何歧义（两种合理实现会产生不同正式输出）→ 立即停止该模块、提交 `AMBIGUITY_REPORT`（含具体分歧反例），等待 v13.0.x errata。**禁止查阅旧版本 SPEC "补全"缺口**——那是把已废除的条款走私回系统；
2. **审查宪法约束你**（SPEC §-1）：你提出的任何问题必须是 A 类（输出分歧反例）或 B 类（统计判词反例）；"我觉得有更好的方法"→ 写入 §17 登记簿，不阻塞、不实现；
3. **禁触收益方向**：freeze 之前任何真实收益方向的读取都是污染。你会接触真实行情数据（快照、单位锚定、合成测试），但任何"信号→未来收益"的连接在 freeze 前只允许出现在合成数据上；
4. **断言先行**：SPEC §12 步骤 2 与 §15 列出的全部合成自检断言，先写测试后写实现，git 历史可查；
5. **Append-only 铁律**：快照库、outcome ledger、Episode/配对/交易记录一经写入永不修改；
6. **不许做的事**：不打 FREEZE tag、不签 RESOLVED_CONFIG、不启动正式影子、不跑 DEV/OOS-B 真实读数（它们在 freeze 之后才解锁）、不调任何冻结参数。

## 工作顺序（依赖序，P0 无条件立即）

### P0：append-only 快照库【今天启动】
- 每交易日收盘后抓取 KPL / DC / THS 全部题材成分快照，append-only + 抓取时间戳（时钟 PIT 字段齐备，SPEC §2.3）；
- 这是全项目唯一不可逆的时钟：Stage-B 需要累计 ≥250 个 self-collected 交易日，8 年墙钟自快照库启动日计；
- 同步开始：数据发布时间监测日志（drift gate 与时钟 PIT 的原料）。

### P1：canonical 数据摄入
单位一次性换算（SPEC §2.4：price=元/股、volume=股[手×100]、amount=元[千元×1000]、turnover=小数、mcap=元）；下游禁止出现原始单位；单位锚定用外部公开数据点核验并写入 DATA_AUDIT。

### P2：主源普查与评分卡
`CONCEPT_DATA_CENSUS.md`：三源快照可得性/覆盖/ID 稳定率实测 → 按 SPEC §2.1 评分卡机械选定主源与第二源；`vendor_reconstructed_history` 与 `self_collected` 标签落库。

### P3：合成边界测试集 + 八哈希裁判台【先于双实现存在】
- 构造合成测试数据（含 SPEC 全部边界样例：指派反例 A→B 合格 B→A 不合格、一字非涨停日、池=3/4/1/0、涨停替补链、退市/停牌/换股、SMD 临界、α 转移序列……）；
- 实现 §16.1 八张正式输出表的哈希生成器（daily_universe / concept_cluster / signal / episode / matching / trade_ledger / court_sample / verdict）——**裁判台必须独立于两个实现**。

### P4：引擎实现（单实现阶段）
按 SPEC §2→§11 顺序实现全链，强制单测清单（SPEC §12 步骤 2 + §15）逐条绿灯。重点点名（十五轮审查中付过学费的）：
- MarginalUniverse / FWERFamily 分离断言（CoordinationState 对全部合格题材可算）；
- 候选边题材零重叠断言（同题材成员互换轨迹 = 零模型灵魂失效）；
- 完美指派反例断言（S\* 必须 =2 的两股票场景）；
- α_spent 每次开庭无条件更新断言（构造"两次未拒绝开庭 + 收转移 α"序列，对照边界引擎手算）；
- B 阶梯与 B≥⌈100/α⌉ 一致性断言（α=0.0005 → 250k 档）；
- Gate0-Z 四单测（B 臂解析等价等）；
- 时间轴断言（持有日 1..10 = D0+5..D0+14）；
- canonical 单位断言（手/千元换算样例）。

### P5：双 Agent 分叉
P3 裁判台 + P4 参考实现就绪后，第二个 Agent **从零、仅凭 SPEC** 独立实现（两实现间禁止代码共享与直接沟通，唯一合法通道 = AMBIGUITY_REPORT）。

### P6：验收
- §16.1：同一冻结测试数据 → 双实现 → 八哈希逐表比对；不一致 → 三分类定位 {SPEC 歧义 | 代码错误 | 数值实现差异}，仅第一类触发 errata；
- §16.2：统计压力测试——在 SPEC §10 预注册的混合真假配置族（含灰区 θ∈(0,MES)×4、护栏失败配置）下验证 P(错误经济 full-pass) ≤ α_r ∧ P(错误死亡) ≤ β_r，并逐节点对照 §1.4 十项表核验判词人群 = 样本 = estimand；
- 两项通过 → 提交 `QUALIFICATION_REPORT` → 等待项目所有者宣布 QUALIFIED / FREEZE APPROVED。

## 你最可能踩的坑（十五轮审查的血泪压缩）

1. **拿旧版本 SPEC 补缺口**——v1-v12.1 的条款可能与 v13.0.1 冲突（这正是历史上三次"压缩回归"的来源）。缺什么就报什么，别自己补；
2. **把"优化建议"当阻断**——宪法已冻结：只有输出分歧反例和统计判词反例才是阻断项，其余进登记簿；
3. **在验收前偷看真实收益**——合成数据足以测试一切装置逻辑；真实收益方向的第一次合法读取在 freeze 之后；
4. **浮点 tie-break**——排序、匹配、指派的全部并列必须按 SPEC 的 ID 字典序规则处理（int64 量化成本、稳定排序），否则八哈希必然分叉；
5. **单位**——手/千元/元的换算错误曾让整个前代项目两轮迭代颗粒无收（V12 复盘教训 #8），摄入层一次换算 + 断言。

有疑问且 SPEC 未覆盖时：这就是 AMBIGUITY_REPORT 的定义，停下来写报告——你发现的每一个真歧义都是在替双 Agent 验收省一次分叉返工。
